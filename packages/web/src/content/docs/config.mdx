## Overview

OpenCode can be configured through JSON configuration files. The configuration system is flexible, allowing you to customize everything from keybindings to AI model settings.

## Configuration Files

OpenCode looks for configuration in several locations, loaded in order of precedence (later files override earlier ones):

1. **Global user config** - `~/.config/opencode/opencode.json`
2. **Project configs** - `opencode.json` or `opencode.jsonc` files found by walking up from the current directory
3. **`.opencode/` directory** - Special directory containing commands, agents, modes, and plugins
4. **Managed configs** - Enterprise/admin settings from system directories

### File Format

Configuration files use JSON with comments (JSONC) and follow this structure:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-3-5-sonnet",
  "theme": "dark"
}
```

The `$schema` field enables IDE autocomplete and validation. It's automatically added if missing.

## Core Settings

### Model

Set your default AI model:

```json
{
  "model": "anthropic/claude-3-5-sonnet",
  "small_model": "anthropic/claude-3-haiku"
}
```

The `small_model` is used for lightweight tasks like title generation.

### Theme

Choose your interface theme:

```json
{
  "theme": "dark" // or "light", "system"
}
```

### Keybindings

Customize keyboard shortcuts:

```json
{
  "keybinds": {
    "submit": "enter",
    "newline": "shift+enter",
    "escape": "ctrl+c"
  }
}
```

See [Keybindings](/docs/keybindings) for the full list of configurable shortcuts.

## Providers

Configure AI provider settings and API keys:

```json
{
  "provider": {
    "openai": {
      "options": {
        "apiKey": "sk-..."
      }
    },
    "anthropic": {
      "options": {
        "apiKey": "sk-ant-..."
      }
    }
  }
}
```

### Provider Options

Each provider supports these options:

- `apiKey` - API authentication key
- `baseURL` - Custom API endpoint (for proxies or self-hosted models)
- `whitelist` - Array of allowed model names
- `blacklist` - Array of blocked model names

### Model Overrides

Override specific model settings:

```json
{
  "provider": {
    "openai": {
      "models": {
        "gpt-4": {
          "temperature": 0.5,
          "maxTokens": 4000
        }
      }
    }
  }
}
```

## Agents

Configure AI agents for different tasks:

```json
{
  "agent": {
    "build": {
      "model": "anthropic/claude-3-5-sonnet",
      "temperature": 0.7
    },
    "plan": {
      "model": "openai/gpt-4",
      "temperature": 0.5
    }
  }
}
```

See [Agents](/docs/agents) for detailed agent configuration.

## Commands

Create custom slash commands:

```json
{
  "command": {
    "review": {
      "template": "Please review this code:\n\n{{input}}",
      "description": "Review code for issues",
      "agent": "build"
    }
  }
}
```

See [Commands](/docs/commands) for the full command syntax.

## MCP Servers

Configure Model Context Protocol servers:

```json
{
  "mcp": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/files"]
    }
  }
}
```

See [MCP](/docs/mcp) for more details.

## Plugins

Load plugins by specifying their npm package names:

```json
{
  "plugin": [
    "@opencode-ai/plugin-example"
  ]
}
```

Plugins are loaded from `node_modules` and can extend opencode's functionality.

## Advanced Configuration

### Log Level

Control verbosity of logs:

```json
{
  "logLevel": "info" // "debug", "info", "warn", "error"
}
```

### Watcher

Configure file watching behavior:

```json
{
  "watcher": {
    "ignore": ["node_modules", ".git", "dist"]
  }
}
```

### Server

Settings for `opencode serve`:

```json
{
  "server": {
    "port": 8080,
    "host": "localhost"
  }
}
```

### TUI Settings

Customize the terminal UI:

```json
{
  "tui": {
    "layout": {
      "sidebar": {
        "width": 40
      }
    }
  }
}
```

## Variable Substitution

### Environment Variables

Use `{env:VARIABLE_NAME}` to substitute environment variables:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "openai": {
      "options": {
        "apiKey": "{env:OPENAI_API_KEY}"
      }
    }
  }
}
```

If the environment variable is not set, it will be replaced with an empty string.

---

### Files

Use `{file:path/to/file}` to substitute the contents of a file:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["./custom-instructions.md"],
  "provider": {
    "openai": {
      "options": {
        "apiKey": "{file:~/.secrets/openai-key}"
      }
    }
  }
}
```

File paths can be:

- Relative to the config file directory
- Or absolute paths starting with `/` or `~`

These are useful for:

- Keeping sensitive data like API keys in separate files.
- Including large instruction files without cluttering your config.
- Sharing common configuration snippets across multiple config files.

---

### Imports

Use `{import:path/to/file.json}` to import entire JSON objects from external files:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": "{import:./providers.json}",
  "agent": {
    "custom": "{import:./custom-agent.json}"
  }
}
```

The imported file must contain valid JSON. The contents are parsed and inserted as the value at the location of the `{import:...}` placeholder.

Import paths follow the same rules as file paths:

- Relative to the config file directory
- Absolute paths starting with `/` or `~`

Imported files can also contain `{import:...}`, `{file:...}`, and `{env:...}` references, which will be resolved recursively. Circular imports are detected and will throw an error.

This is useful for:

- Splitting large configurations into modular files.
- Sharing common provider/agent configurations across multiple projects.
- Keeping sensitive configuration separate from your main config file.
